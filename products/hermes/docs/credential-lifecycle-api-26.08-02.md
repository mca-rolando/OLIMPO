# HermesDDNS 26.08-02 — Credential Lifecycle Admin API

This block connects the credential lifecycle core to the HTTP server while preserving DDNS compatibility.

## Security behavior

A rotation request no longer creates or returns a replacement DDNS secret from the administrative API. The existing DDNS credential remains active while the rotation is in `requested` state.

The replacement secret will be generated by the Hermes Agent in a later agent/API block. Hermes receives only the candidate Key ID and SHA-256 hash, preserving the rule that DDNS secrets are not stored plaintext by the server.

The legacy route `/api/v1/devices/:id/credentials/rotate` is retained as an alias, but now uses the safe asynchronous lifecycle behavior and does **not** return an `api_key`.

## Administrative endpoints

### Request rotation

`POST /api/v1/devices/:id/credential-rotations`

Legacy alias:

`POST /api/v1/devices/:id/credentials/rotate`

Optional JSON body:

```json
{
  "grace_minutes": 30
}
```

The response contains the `DDNSCredentialRotation` and `next_action: agent_stage_candidate`. The current credential remains active.

### List rotations for a device

`GET /api/v1/devices/:id/credential-rotations`

### Get one rotation

`GET /api/v1/devices/:id/credential-rotations/:rotation_id`

### Roll back a rotation

`POST /api/v1/devices/:id/credential-rotations/:rotation_id/rollback`

Optional JSON body:

```json
{
  "reason": "operator cancelled"
}
```

### Reconcile expired grace windows

`POST /api/v1/credential-rotations/reconcile`

This revokes previous DDNS credentials whose grace windows have expired and marks their rotations `completed`.

A later runtime block will schedule reconciliation automatically; this endpoint provides an explicit administrative primitive in the meantime.

## DDNS validation integration

When a candidate credential is in `validating`, a successful DynDNS operation (`good` or `nochg`) using that credential causes Hermes to call `ConfirmCredentialUse`.

Only after the DDNS operation succeeds does the lifecycle advance:

```text
replacement: active + confirmed
previous:    active -> grace
rotation:    validating -> grace
```

If lifecycle confirmation itself encounters an internal database error after the DDNS operation has already succeeded, Hermes logs the lifecycle error but preserves the successful DynDNS response. The next DDNS update can retry lifecycle confirmation.
